SYSTEM OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Current Limitations:
  • Single user design
  • No caching - every query hits external APIs
  • High latency (6-8 seconds per request)

  ✅ Multi-user support with authentication
  ✅ Redis caching layer for instant responses
  ✅ PostgreSQL database for persistent storage
  ✅ Query result caching with TTL
  ✅ 70%+ cache hit rate target
  ✅ Sub-20ms response time for cached queries
  ✅ 400x performance improvement
  ✅ 70% cost reduction

DATABASE SCHEMA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Table: users
  • id (UUID, PK)
  • email (VARCHAR, Unique)
  • api_key (VARCHAR, Indexed)
  • rate_limit_tier (VARCHAR)
  • created_at, last_login (TIMESTAMP)

Table: queries
  • id (UUID, PK)
  • user_id (UUID, FK → users.id)
  • query_text (TEXT)
  • query_hash (VARCHAR, Indexed)
  • created_at (TIMESTAMP, Indexed)
  • execution_time_ms (INTEGER)

Table: search_results
  • id (UUID, PK)
  • query_id (UUID, FK → queries.id)
  • query_hash (VARCHAR, Indexed)
  • query_date (DATE, Indexed)
  • headlines (JSONB)
  • meta (JSONB)
  • created_at, expires_at (TIMESTAMP)

Table: sentiment_results
  • id (UUID, PK)
  • search_result_id (UUID, FK → search_results.id)
  • sentiment_summary (JSONB)
  • per_item_analysis (JSONB)
  • created_at, expires_at (TIMESTAMP)

Table: reports
  • id (UUID, PK)
  • sentiment_result_id (UUID, FK → sentiment_results.id)
  • fact_check, bias_check, forensic_analysis (TEXT)
  • created_at, expires_at (TIMESTAMP)

Table: query_cache_stats
  • query_hash (VARCHAR, Indexed)
  • hit_count, miss_count (INTEGER)
  • last_accessed (TIMESTAMP)
  • avg_response_time_ms (INTEGER)


CACHE STRATEGY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Cache Key Format:
  "query:{hash(query)}:{date}"
  Example: "query:a3f5b9c2:2025-10-31"

TTL (Time To Live):
  • News queries: 1 hour
  • Popular queries (hit_count > 100): 30 minutes
  • Historical queries (date < today): 24 hours

Cache Invalidation:
  • Automatic expiration via TTL
  • Date-based (new day = new cache key)
  • Manual via admin API
  • Proactive refresh for popular queries

Benefits:
  • Same query within 1 hour = instant response
  • Different users benefit from each other's searches
  • Reduces API costs by 70%+
  • Improves response time by 400x
